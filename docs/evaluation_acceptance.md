# 评测与验收计划

## v0.4.1 已执行基线

- 后端：24 项单元/API 测试，新增公共 HTTP、ADS-B、METAR、来源识别、空间绑定、官方通告与
  高德路线时间窗覆盖；
- Web：Biome、TypeScript、生产构建和 3 条 Playwright 纵向流程；
- 小程序：12 项 Node 单测、项目结构检查和全部 JavaScript 语法检查；
- 契约：FastAPI OpenAPI 导出与 TypeScript 客户端生成；
- 部署：Docker/阿里云健康与功能 smoke 脚本；
- 安全：额外字段 fail closed、无客户端密钥、无行程 Storage、上传类型/大小、动作二次确认。
- 真实联网：只读脚本实际取得 ZBAA METAR 和浦东周边 ADS-B 航空器列表；结果按时间戳记录，
  不进入普通 CI。
- 高德：固定响应契约覆盖 ETA、距离、TMC 路况、失败降级和预计离家前 3 小时时间窗；阿里云
  上线后使用北京望京公开测试点至首都机场 T3 完成一次真实联网验证。

这些结果证明“功能预览”闭环，不替代真实航班/交通供应商合同测试、50 条 Gold Cases、真机
双平台验收、提醒投递或真实试点校准。

## 1. 评测分层

不能用单一“回答准确率”验收。分为：

1. 数据契约；
2. 行程抽取；
3. 来源适配器；
4. 决策计算；
5. 证据与核验；
6. 模型增益；
7. 前端/小程序体验；
8. 可靠性、安全和恢复；
9. 真实试点校准。

## 2. Gold Cases

### P0：20 条决策纯函数

覆盖：

- 无托运行李/有托运行李；
- 标准/稳妥/非常稳妥；
- 已知/未知登机口；
- 单航站楼/复杂航站楼；
- 道路 P50/P90/P95；
- 下雨/活动/封路；
- 值机与登机约束谁更早；
- 跨午夜和时区；
- 缺数据与冲突；
- 固定点迭代不收敛。

### P1：50 条端到端

每条检查：

- `TripCandidate`；
- 用户确认门；
- 工具集合和参数；
- 规范化 Observation；
- 绑定约束；
- 最终时间和分项；
- Evidence lineage；
- Verifier；
- 页面文案与动作等级；
- 模型关闭时的结果。

### P2/P3：100 条

新增：

- 供应商限流、超时、字段缺失/变更；
- 航站楼和起飞时间变更；
- 数据撤回/乱序；
- 缓存过期；
- 外部 API 全断；
- 模型响应非法；
- 多用户对象隔离；
- 提醒幂等；
- 删除和备份恢复；
- 云端重启/回滚。

## 3. 目标指标

以下是准入目标，不是当前已达成结果：

### 契约和安全

- Schema 有效率：100%；
- 未登记工具执行：0；
- 模型自由 SQL/URL：0；
- 精确建议的证据覆盖：100%；
- 未经用户确认的外部动作：0；
- 客户端/日志/Git 秘密泄露：0；
- 越权访问测试通过率：100%。

### 行程抽取

- 航班号、日期、机场、计划时间字段精确率目标 ≥ 98%；
- 航站楼字段精确率目标 ≥ 95%；
- 低置信字段必须进入确认，不能静默采用；
- 敏感非必要字段保留率：0。

### 决策

- 确定性 Gold Cases：100%；
- 同一输入/版本可重放一致率：100%；
- 任何建议都满足值机/登机硬约束：100%；
- 交通预测区间在试点中的覆盖率接近对应目标分位数；
- 危险晚到率设为最高优先级指标，阈值由试点评审确定；
- 过早等待也纳入成本，防止一味“无限提前”。

### 可用性

- 本地确定性 API p95 < 500 ms；
- 不含模型的外部数据决策 p95 < 5 s；
- 模型解释异步完成，不阻塞先展示确定性结论；
- staging 月可用性目标 ≥ 99.0%；
- 提醒调度延迟 p95 < 2 分钟；
- 重复提醒率 < 0.1%。

## 4. 模型 A/B

基线组合：

1. FakeProvider + 模板；
2. `gpt-5.6-sol` medium + 原提示；
3. `gpt-5.6-sol` low + 原提示；
4. 仅在实测失败后做最小提示修订；
5. 可选境内 Provider 对照。

测量：

- 结构化输出有效率；
- 实体/字段抽取；
- 工具路由；
- 是否添加未证实事实；
- 对 Evidence 的忠实度；
- 用户理解度；
- p50/p95 延迟；
- 输入/输出/reasoning/cache token；
- 每个成功任务成本。

模型必须证明相对确定性基线的净增益。模型不可用时，核心决定不能消失。

## 5. 供应商合同测试

每个适配器具有固定 fixture 和回放：

- success；
- no data；
- partial；
- stale；
- conflict；
- 401/403；
- 429；
- 5xx；
- timeout；
- malformed；
- schema drift；
- duplicated/out-of-order update。

真实调用只在受限 shadow pipeline 中执行，记录配额但不保存敏感正文。

## 6. 前端验收

Playwright：

- 创建、确认、编辑、删除行程；
- 上传安全/非法文件；
- 显示建议和证据；
- 调整风险偏好后的差异；
- 航站楼变更；
- 来源过期与冲突；
- 模型降级；
- API/网络错误；
- 隐私导出和删除；
- 键盘、移动端布局和基本无障碍。

小程序：

- request 合法域名严格开启；
- health → capabilities → login/session；
- Android/iPhone 真机；
- 上传、行程、建议、订阅提醒、取消和删除；
- 冷启动、网络切换、超时、体验版升级。

## 7. 云端验收

- 公网只开放 80/443；
- HTTPS、证书链和续期；
- 无认证/越权返回正确；
- API/worker/web 单独重启；
- 既有客流站点不受影响；
- 外部 API 熔断和恢复；
- 数据库备份恢复；
- 上一镜像回滚；
- Mac 关机不影响；
- 日志中抽样确认无敏感字段；
- SLS/CMS 告警能到达批准人员。

## 8. 试点设计

建议 20–50 人，3–5 个机场，至少 8 周：

- 用户必须知道系统处于试点，结果需复核；
- 采集实际出发/到达需单独同意；
- 每个危险误差人工复盘；
- 按机场、航站楼、时间、天气、风险偏好分层；
- 不能只观察“用户是否喜欢”，还要观察区间校准；
- 不使用试点数据训练模型，除非另行同意。

## 9. 阶段退出报告

每个阶段输出：

- 源码 commit 和 release；
- 功能/限制；
- 测试命令和结果；
- Gold Cases 指标；
- 数据源/模型/成本；
- 安全和隐私检查；
- 未关闭风险；
- 回滚和恢复证据；
- 下一阶段 Go/No-Go。
