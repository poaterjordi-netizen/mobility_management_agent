# 安全、隐私与合规计划

本文件是工程计划，不替代中国执业律师的正式法律意见。

## 1. 数据分类

| 等级 | 示例 | 控制 |
| --- | --- | --- |
| Public | 机场名称、公开天气、道路公告 | 来源/许可/完整性 |
| Internal | 配置、聚合指标、脱敏错误 | 最小权限 |
| Personal | 用户账号、一般偏好、行程 | 目的限制、访问控制、删除 |
| Sensitive | 精确住址/坐标、连续轨迹、票号、订单、证件 | 单独同意、加密、最小化、严格审计 |
| Secret | API Key、AppSecret、密码、私钥 | Secret Manager/Keychain，禁止进 Git |

行踪轨迹属于敏感个人信息。即使只服务单个用户，也按高等级设计。

## 2. 隐私原则

- 明确目的：只为行程发现、出发决策、提醒和用户选择的个性化；
- 最小必要：模型不需要知道姓名、票号、完整住址；
- 分步同意：行程、位置、截图、日历、通知、提醒、历史个性化分别授权；
- 易于撤回：关闭来源后停止拉取，关闭提醒后取消未来任务；
- 可访问/更正/删除/导出；
- 短期保留原始材料，长期只留最小结构化字段和脱敏统计；
- 不把数据用于训练，除非有单独、明确、可撤回同意；
- 默认不跨境；任何境外模型调用由政策引擎控制。

## 3. 数据最小化流程

截图：

```text
上传
→ 恶意文件检查
→ OCR
→ 识别航班/日期/机场/航站楼
→ 遮盖姓名/证件/票号/订单
→ 用户确认
→ 删除原图和非必要 OCR 文本
```

位置：

- 客户端显示家庭/公司别名；
- 数据库加密保存必要坐标；
- 日志只保存城市、粗栅格或 hash；
- 地图供应商只接收完成算路必需的坐标；
- 模型只接收“到机场道路 P90=xx 分钟”等派生事实。

## 4. 模型数据出域

Provider 调用前生成 `ModelEgressRecord`：

- purpose：`semantic_compile` 或 `evidence_synthesis`；
- 用户/租户 scope hash；
- provider、model、endpoint target hash；
- payload schema 和字段白名单；
- 是否含 personal/sensitive 数据；
- policy version；
- request/response hash、状态和 token usage。

默认：

```text
intent egress   = deny
evidence egress = deny
```

只有门禁批准后才发送最小化内容。原始截图、完整地址、账号、票号、订单、通知正文、精确轨迹
永不发送给模型。若跨境条件不满足，使用 FakeProvider/确定性模板或经批准的境内 Provider。

## 5. 威胁模型

| 威胁 | 失败方式 | 控制 |
| --- | --- | --- |
| Prompt 注入 | 截图/公告诱导模型调用危险工具 | 数据与指令分离，工具白名单，参数 Schema |
| 幻觉时间 | 模型编造登机/出发时间 | 决策纯函数 + Verifier |
| 错误来源 | 把旧网页/社交帖当实时事实 | source registry、TTL、可信等级 |
| 账号接管 | 读取他人行程 | 服务端身份、owner/tenant/scope 校验 |
| IDOR | 猜 trip/run/evidence ID | 每对象授权和不可枚举 ID |
| 上传攻击 | 恶意图片/压缩炸弹 | 类型/尺寸限制、隔离解析、超时 |
| 位置泄露 | 日志或 Trace 暴露住址 | 字段加密、脱敏、日志 lint |
| 小程序本地缓存泄露 | 行程或精确地址进入 Storage/备份 | 合成版只用运行内存；Storage 仅保存非敏感环境枚举 |
| 秘密泄露 | Key 进入 Git/客户端 | Secret Manager、push protection、构建检查 |
| SSRF | 模型或用户控制外部 URL | 固定供应商主机和 allowlist |
| 供应链 | 依赖/镜像漏洞 | lockfile、SBOM、CodeQL、扫描 |
| 重复提醒/动作 | 重试产生多次消息或下单 | idempotency key、Outbox、动作确认 |
| 数据删除不完整 | 备份/OSS 留存 | 删除编排、生命周期、恢复后重放删除 |
| 成本攻击 | 大量模型/地图/刷新调用 | 用户/来源限流、预算、缓存、熔断 |
| 供应商被替换 | endpoint 配置漂移 | provider/model/target hash 绑定 |
| 公共数据污染 | ADS-B 覆盖错误、旧 METAR 或通告误匹配 | 独立语义、TTL、置信度、原文链接、有限权重 |

### v0.4.0 公共来源控制

- 只允许 `api.adsb.lol`、`aviationweather.gov`、`api.open-meteo.com` 和
  `restapi.amap.com` 固定 HTTPS 主机；
- 响应最大 1.5 MB，默认 6 秒超时、一次重试、短 TTL 缓存和供应商级熔断；
- ADS-B 只在用户同意、计划起飞前 3 小时至后 8 小时且航司呼号可映射时查询；
- 起飞前发现的同号航空器若距计划出发机场超过 200 km，会拒绝绑定，防止航班号复用误配；
- ADS-B 不修改计划起飞、值机截止、登机或登机口字段；
- METAR 与未来预报使用不同 Schema 和卡片，禁止时间语义混用；
- 官方通告只从代码审查过的配置读取，地点关键词只产生“可能相交”；
- 每条公共证据包含来源 URL、观测时间、完整性、置信度和许可说明。

## 6. 第三方 App 边界

不得：

- 逆向私有 API；
- 绕过验证码、反爬或设备校验；
- 收集用户第三方密码/Cookie；
- 用辅助功能服务批量控制其他 App；
- 以用户登录身份批量抓取社交内容；
- 在平台条款禁止时缓存、再分发或训练。

可以在明确授权下评估：

- 用户主动分享/上传；
- Android 系统通知监听；
- iOS Share Extension/Shortcuts；
- 官方 URL Scheme/Universal Link；
- 官方开放 API 或商业合作接口。

## 7. 自动动作

动作分级：

| 等级 | 示例 | 策略 |
| --- | --- | --- |
| R0 | 查看、计算、解释 | 自动 |
| R1 | 生成提醒预览、地图链接 | 自动生成，不外发 |
| R2 | 发送已订阅提醒 | 用户授权 + 幂等 |
| R3 | 打开预约页面并预填 | 用户点击 |
| R4 | 创建可取消预约 | 单次明确确认 + 官方 API |
| R5 | 付款、退改签、不可逆操作 | 首版禁止，未来强化确认 |

模型只能提议 R1–R3。R4/R5 即使以后开放，也由确定性策略和用户界面确认执行。

## 8. 合规工作包

P0/P1：

- 数据地图、处理目的、保留期限；
- 隐私政策草案；
- 用户同意和撤回模型；
- 开源/第三方依赖清单；
- 数据出域默认 deny。

P2：

- 每个供应商的数据许可和合同评审；
- 个人信息保护影响评估（PIPIA）；
- 截图/OCR 和位置处理评审；
- 真实用户 shadow 同意文本。

P3：

- 阿里云区域、备案、等保适用性评估；
- 数据库/OSS/日志访问控制；
- 备份、删除、事件响应；
- 境外模型调用条件与替代方案。

P4/P5：

- 微信小程序隐私保护指引和平台审核；
- 订阅消息与登录合规；
- 用户投诉/举报和客服流程；
- 生成式 AI 服务、算法备案/安全评估适用性法律判断；
- 原生 App 商店政策预审。

### v0.3.0 无状态客户端基线

`clients/wechat-miniprogram` 当前实现不会调用 `wx.setStorageSync` 保存行程、地址或决策。
唯一允许持久化的值是版本化的 `production`/`local` 环境枚举；API 地址由代码中的固定
allowlist 映射，用户不能输入任意 URL、令牌或 AppSecret。截图 OCR 已实现为受尺寸/类型/
超时约束的本地临时处理；提醒当前为 ICS/复制预览；地图为二次确认的官方 URI。正式身份、
微信订阅投递和商业实时数据仍受各自门禁约束。

### v0.4.1 高德位置与凭据控制

- 只有用户开启本次实时同意且提供完整经纬度时才调用高德，不发送文字住址；
- 当前驾车路线只在预计离家时刻前 3 小时内查询，避免把当前路况当作晚间预测；
- 未来路径规划高级服务在企业权限与合同未落实前保持禁用；
- Key 不进入 Git、Web 或小程序，只写入阿里云 `/etc/mobility-management-agent/runtime.env`；
- 运行时文件必须由 root 持有且权限为 `0600`，否则部署脚本拒绝启动；
- 高德控制台将 Key 绑定到阿里云服务器出口 IP；
- Key 当前只用于短期、小流量测试；商业运营前必须完成许可、配额与 PIPIA 审查；
- 响应只保留归一化 ETA、距离和拥堵摘要，不持久化完整路线轨迹。

### 微信小程序 v0.4.2 旧状态与测试数据控制

- 空会话不再从服务端自动载入演示行程，避免测试数据被误认为用户当前行程；
- 导入流程必须先提供去机场的出发地，再解析已订航班通知，候选仍需用户确认；
- 北京交大—首都机场—大连—大连理工一键案例是公开点位验收数据，并在界面明确标为测试；
- 一键案例与版本化 Gold Case JSON 由契约测试保持一致，不包含订单号、票号或个人住址；
- 用户清空会话后同时清除行程、决定、候选和完整旅程展示标志，不自动恢复案例；
- 完整旅程卡只给出地图路线入口，不自动叫车、下单或付款。

## 9. 事件响应

事件级别：

- SEV-1：大规模行程/位置泄露、错误动作、系统性危险建议；
- SEV-2：供应商数据污染、提醒大面积失败、对象越权；
- SEV-3：单用户错误、过期证据、非敏感可用性问题。

流程：

1. 停止相关数据源/提醒/动作；
2. 保全脱敏审计；
3. 确认影响用户和时间窗；
4. 按法律/合同决定通知；
5. 修复、回归和恢复；
6. 无责复盘并更新 Gold Cases/门禁。

## 10. 保留建议

最终期限需由法务和业务确认。工程默认建议：

- 原始截图/OCR 全文：确认后尽快删除，最长 24 小时；
- 活跃行程：行程结束后 30 天；
- 精确位置：只在活跃行程和最小必要期内；
- 脱敏决策与评测：90 天；
- 安全/访问审计：按合规要求，严格限制；
- 备份：短周期滚动，并支持删除标记重放。

用户主动删除优先于常规期限；必须告知备份中的技术删除周期。
